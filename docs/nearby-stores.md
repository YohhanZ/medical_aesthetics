# 附近门店匹配

客户咨询页和登录页共用 `frontend/customer/src/components/StorePicker.vue`。

- 浏览器已授予定位权限时，自动匹配一次；尚未授权时显示“定位附近门店”，点击后由浏览器申请权限。不反复弹出授权，不通过 IP 猜位置。
- 首次新建匿名连接、没有 URL 指定门店、登录信息尚未填写且位置精度合理时，自动选用最近门店。已有身份、指定门店或正在填写登录信息时，只推荐并预选，用户点击“确认切换门店”。切换门店需重新登录，不删除原门店记录。
- 使用 WGS84 经纬度和 Haversine 球面距离，显示约数、直线距离，不表示路程或交通时间。坐标缺失的门店仍可手选，但不参与距离排名。
- 用户坐标仅在浏览器回调中临时计算，不写入浏览器存储、服务端、行为事件、长期记忆或模型请求。不自动调用地图或地理编码供应商。浏览器/操作系统定位本身遵循其授权与定位服务设置。
- 拒绝授权、定位超时、不安全上下文、浏览器不支持时，保留手动选店。定位误差大于 5 公里时提示精度较低，并不自动切换。手动修改选项、切换身份或离开页面后，迟到结果不会覆盖选择。

## 门店数据

迁移 `backend/migrations/015_store_locations.sql` 为 `store` 添加 `city`、`address`、`latitude`、`longitude`，经纬度成对设置且限制范围。`GET /api/public/stores` 在原有启用状态、模拟数据过滤规则内公开这些字段，并返回 `coordinate_system: "WGS84"`。未配置坐标时返回 null。

`app.seed.seed_store_locations` 仅为已有两家模拟门店补城市级示例点：上海 31.23/121.47，杭州 30.25/120.15。它们不是美丽田园真实门店位置，不可导航；不会覆盖已配置坐标。已有本地演示库在备份、迁移后可单独调用该函数，无需重置或重新导入业务资料。

上线前由机构提供真实门店公开地址与 **WGS84** 坐标，再通过受控的数据维护流程配置。当前没有新增门店地址管理后台。高德/腾讯的 GCJ-02 或百度 BD-09 坐标不能直接填入 WGS84 字段。

## 环境和验证

定位要求浏览器支持、安全上下文和用户授权；本机 localhost 可开发测试，远端使用有效 HTTPS。浏览器拒绝权限后，用户可在站点权限设置中重新允许。详见 [Geolocation API 文档](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。

测试覆盖距离排序、日期变更线、无效坐标、无权限、超时、迟到回调、首次/已有身份自动选择边界，以及公共门店接口、模拟过滤和数据库坐标约束。供应商地图和真实用户位置不参与自动化测试。
