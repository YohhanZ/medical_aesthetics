# 咨询聊天质量与上下文实测

日期：2026-10-12。当前状态：下列首轮问题已按批修正，最新验证见末尾“修正与复测”。前半保留修正前结果，避免把历史失败删掉。真实医学细节与价格仍受已批准资料限制。

## 实测方法与边界

通过客户5173同源代理→API8001→真实LangGraph/Qwen/Milvus/Neo4j，使用14组固定合成场景、50轮。每组独立匿名访客/新线程，保持组内连续追问，逐轮检查原键重放，最后读取历史并退出。没有姓名、手机号、证号、真实病历或真实客户记录；个人医疗/越权问题由当前本地守卫转接。本批没有提交预约、发送短信、使用外部评判模型或修改主Agent/知识发布状态。

这是人工逐轮审阅，不把HTTP成功、引用通过或模型自评分当作语言/医学质量通过。评分重点：回答当前问题、项目一致、指代连续、总结真实前文、拒绝意愿、话题切换与医疗/业务边界。没有临床正确性批准、容量或SLA结论。

## 可复现缺陷与优先级

### P1：降级答案与当前项目不一致

路径care_hydration：补水→比较清洁→“刚才说的补水，具体服务内容能再说明一下吗？”。实际回答降级为“清洁护理在本地目录中归入生活美容护理”，卡片却为hydration。节点为invalid_model_response。检索对以“刚才”开头的问题拼接上一问，即使本轮已明确补水也保留清洁混合语境；降级直接取第一条证据，没有验证当前主项目。修复需当前显式项目优先，并检查回答/引用/卡片的主题一致；失败时明确缺少本项目资料，不能拿另一项目填充。

### P1：长对话丢失主题后仍给出确定回答

long_context第1轮明确“只想了解补水护理”，随后八轮问流程/费用/来源，第10轮问最初方向。实际答“最初聊的护理方向是首次护理体验沟通”，原问题并非这个方向。代码取最近六条允许外发的用户问题，模型最多看到四条，不提供助手回答；压缩只保留意图/阶段/拒绝邀请等，未保留明确主题锚点。建议保存有来源的公开主题/客户偏好摘要，切换主题时更新；缺来源时承认无法确定，而非从检索结果推测聊天事实。

### P1：专业转接后关联问题失去风险上下文

medical_risk第一轮个人医疗问题转接，第二轮“那换成光子能做吗？”返回泛化澄清。原风险问题禁止外发，因此不在公开问题上下文中；压缩也没有保留非敏感的转接原因标记。应在本地保持必要的风险类别/转接状态，关联个人评估继续专业处理；不得为修复上下文而把原个人医疗正文送给模型。

### P2：项目别名与否定语义识别不足

“光子嫩肤一般有哪些风险需要专业人员说明？”第一问返回“你想了解哪方面”，常见项目词光子/光电未列入当前相关性词表。“先介绍一下咨询流程，不给我定治疗方案”和“我不需要你判断适合性，只想了解门店咨询流程”因裸关键词/跨句正则被误判。应区分公开流程咨询、明确个人评估与否定请求，维持医学边界；通用医学证据不足仍说明待审/需专业资料，而不是不识别项目或假定为个体判断。

### P2：助手输出不进入允许的对话语境

assistant_reference第二步碰巧接对，但一句话总结回错。当前模型只有近期用户问题，不能可靠定位助手此前列出的步骤。需要经过公开内容校验的对话摘要与来源引用；不能把内部业务、身份或医疗记录放入摘要。

### P2：表达重复且项目介绍缺实质信息

多轮护理与医美回复重复“目录归类、只提供了解入口、具体事项待核验”。光电区别问题没有讲清两种了解方向的区别；注射比较的“是的”容易误读。保持真实资料/模拟标识，但把直接回答放在前面，减少重复句；需要独立批准的运营资料和医学资料才能增加有效事实，后台未发布演示价不是当前Agent证据，不能直接搬入真实报价。

### P2：业务转接原因与展示模板不匹配

“是否一定付款”被归为human_or_business；“帮我取消我的预约”转接后展示“缺少可核验资料”。应把公开收费流程与实际付款/取消动作区分，实际业务请求显示对应处理原因/已有受控业务入口，不误说成知识缺失。不得仅依据聊天文字取消预约。

## 页面复现与后续验收

实际浏览器另开测试标签，创建新对话：补水介绍正常→“先介绍一下咨询流程，不给我定治疗方案”出现错误专业转接。截图runtime/chat-quality-browser.png；原对话与业务未修改，没有提交新的申请。浏览器这两轮是额外复现，不计入上面50轮。使用原始三轮/十轮序列复测，不能只验证某句关键词或接口200。

建议下一批优先修复P1主题/降级一致性、有来源公开主题记忆和本地风险状态，再修否定/别名/业务意图与表达。重跑完整50轮并复核原缺陷；新增确定性回归覆盖跨窗口主题、显式切换、降级首证据错项目、专业转接后追问及否定流程。知识状态/门店权限/出口/客户确认门槛保持有效。M6运维计划保留，当前问题修复不能由模拟数据绕过医学批准。

复现：backend目录执行 `..\.venv\Scripts\python.exe -u -X utf8 -m scripts.chat_quality_check`，真实模型会产生调用；单例 `--case long_context` 或 `--case care_hydration` 另存报告，不覆盖全量结果。每次使用合成问题/新访客，不读取既有客户数据。最终脚本通过另一个memory_isolation真实一轮验证GET本人运行trace采集，另存runtime/chat-quality-memory_isolation.json；它也不计入50轮。
