# 客户前端与机构后台

所有前端源码、素材和前端构建配置集中在 `frontend/`。这里是 npm workspace 根目录，客户平台与机构后台为两个独立 Vue 3 / TypeScript / Vite 应用。仓库根 `package.json` 只转发常用命令，不放应用依赖。

```text
medical_aesthetics/
├── frontend/
│   ├── package.json             # 两个 workspace、统一工具依赖
│   ├── package-lock.json        # 唯一前端锁文件
│   ├── customer/                # 客户咨询平台
│   │   ├── src/                 # 真实客户聊天、目录卡片、API 与会话状态
│   │   ├── public/images/       # 网页图片
│   │   ├── assets/source-images/ # 原始生成素材（不打包进网页）
│   │   ├── index.html
│   │   ├── vite.config.ts
│   │   ├── tsconfig.json
│   │   └── package.json
│   └── admin/                   # 机构运营后台
│       ├── src/
│       │   ├── layouts/         # 导航、门店切换与账号入口
│       │   ├── views/           # 登录、工作台、预约、客户、回访、项目、知识、设置
│       │   ├── components/      # 抽屉、空状态等通用组件
│       │   ├── services/        # API、身份、知识操作和隔离的演练数据
│       │   ├── styles/
│       │   ├── router.ts
│       │   ├── state.ts         # 仅内存中的员工凭据与当前授权门店
│       │   └── types.ts
│       ├── index.html
│       ├── vite.config.ts
│       ├── tsconfig.json
│       └── package.json
├── backend/                    # FastAPI、应用服务、迁移与集成测试
├── docs/
├── compose.agent-dev.yml
└── package.json                # 仓库常用命令入口
```

客户素材随客户应用放置，不建立第二份拷贝。暂不创建共享组件包：两端布局和权限不同；后续确有重复时再提取 `frontend/packages/`。两个应用都有独立 `dist/`，可以分别部署、分别回滚。生产 `/api` 需要各自反向代理到同一个受权限控制的 API；Vite 开发代理不是生产代理。后台生产客户入口可通过 VITE_CUSTOMER_URL 配置，未配置时品牌不提供错误的本机链接。前端环境变量不能放密钥。

## 启动与检查

在仓库根目录：

```powershell
npm --prefix frontend ci
npm run dev                  # 客户平台 http://127.0.0.1:5173/
npm run dev:admin            # 另一个终端：后台 http://127.0.0.1:5175/#/login
npm run build                # 两端类型检查和生产构建
npm test                     # 两端 Vitest
```

也可进入 frontend 执行 `npm run dev:customer` 或 `npm run dev:admin`。依赖只在 frontend 安装，根目录不执行 `npm ci`。已有 root node_modules/dist 是忽略的旧本机缓存，没有作为源码迁移或提交；构建产物以各应用 dist 为准。

两端 `/api` 在开发时代理到 `http://127.0.0.1:8001`。先启动后端再打开客户页；客户使用匿名 HttpOnly Cookie，不需要员工密码。后端启动、模拟员工账号和种子密码的位置见 [后端说明](../backend/README.md)。本机 5174 已被其他服务占用，因此后台使用 5175，不停止或复用该旧服务。

生产构建预览：在 frontend 执行 `npm run preview --workspace @ma/admin`（5181）或 `--workspace @ma/customer`（5180）。静态预览只验证构建界面，不提供生产 `/api` 代理。

## 当前后台功能

| 页面 | 已实现前端 | 业务接入状态 |
| --- | --- | --- |
| 员工登录 | 登录、错误提示、超时、退出、登录路由保护 | 真实本地 API；凭据仅内存，刷新重新登录 |
| 工作台 | 指标、待办、服务流程入口 | 知识/授权预约计数及 customer_read 授权门店档案总数来自真实 API；未授权不显示为0 |
| 预约管理 | 状态筛选、分页、详情历史、原时间确认/婉拒、联系方式审计、改约提案与到店登记 | 真实本地 API、独立门店权限/审计/版本/幂等；客户本人接受改约或取消 |
| 客户跟进 | 已到店预约建档、档案分页、原/后续意向版本、客户处理历史、追加新版本 | 真实本地 API；customer_read/manage 独立授权，客户在原对话本人确认 |
| 回访管理 | 状态筛选/分页/聚合、当前已确认档案候选、站内计划、客户反馈与内部跟进历史 | 真实本地 API；客户逐次同意/拒绝/反馈/取消及恢复邀请，员工不能解除暂停或代客户确认 |
| 项目目录 | 搜索、新增、编辑、展示/隐藏 | 仅本地演练；新项目默认隐藏，无实际报价或供给承诺 |
| 知识管理 | 按页搜索/筛选、正文/来源、创建新版本、独立审核、发布申请、撤回 | 真实本地 API；模拟资料与审核标识保留，医学批准阻断 |
| 账号与门店 | 仅授权门店与明确权限、门店切换 | 实际来源 `/api/staff/me`；平台管理员不会自动得到门店权限 |
| 演示资料 | 门店/团队、虚构服务价、接待规则、供应商模拟复核与讲解路径、当前门店JSON导出 | 独立只读真实API；有效customer_read、非生产显式模拟环境；未发布到知识库，不替代实际核验 |

本地开发登录页可选择“进入界面演练”，只使用合成数据且不能调用真实 API；状态仅存在当前页面会话，刷新恢复。生产构建移除演练入口，真实 API 请求失败也不自动退回演练。真实登录预约与到店咨询页已接持久业务，独立项目供给/报价维护页面仍仅演练；不能将该原型或本地模拟业务宣称为真实机构已上线业务。

知识操作由授权员工提交后服务端再次校验，按钮禁用和路由守卫只是交互提示。作者不能自审；知识修改创建新版本；发布进入等待投影，由 M2 Worker 完成真实 Milvus/Neo4j 投影并复核后就绪；医学内容不允许模拟批准。操作需核实版本与门店后明确确认，超时提示先刷新核实，不盲目重试业务写入。

## 当前客户功能

M4 首批新增 components/LiveAppointments.vue、services/appointments.ts 及六项单元测试，真实登录与旧 demo 演练明确分开。接待账号需独立预约权限；后台分页及状态筛选、版本/确认历史、掩码及单独审计联系号码读取、按客户原时间确认、带原因婉拒已接 API。未知结果保留原 request_key，禁止另键重复操作；换门店/身份及旧响应清理、只读账号无处理能力。工作台预约数量为服务端聚合，不来自固定样例。当前客户25、后台18项（共43）测试、两端类型/构建通过；实际桌面/手机详情与客户状态同步验收见实施记录。

`customer/src/services/api.ts` 是同源 API 客户端，`conversation.ts` 管理服务端会话与原键恢复，`booking.ts` 管理预约状态及持久幂等请求；`components/ConsultationPanel.vue` 展示真实消息与等待状态，`BookingPanel.vue` 在对话中展示受服务端校验的预约草稿、核验、确认与申请记录，`ProjectCard.vue` 展示当前目录，`App.vue` 保留首页风格与详情路由。已删除固定示例回答和早期演示预约表单。

首次进入创建门店限定的持久匿名访客；刷新恢复自己的最近对话，支持新对话、历史切换及加载更早消息。浏览器仅保存 visitor/thread 引用，正文在服务端；凭据失效明确提示重新连接，不凭引用恢复权限。选择另一门店后需明确点击切换，新匿名凭据结束旧门店访问。接口失败展示安全错误，不退回示例数据。
